# crm-backend audit

Scope: CRM backend (contacts, leads, deals, line items, pipeline stages, quotes, products, tasks, tickets, activities, sequences CRUD, segments, lead forms + public forms, custom fields, custom reports, saved views, search, crm-data import/export, crm-analytics, crm-customization, crm-permissions/recordScope, sales inbox, lead distribution, gamification, forecast, insights helpers).

Method: read every route/controller/service in scope. Listed every `findUnique/update/delete/updateMany/deleteMany` call in those services (78 call sites) and checked each one is preceded by a `workspaceId`-constrained lookup. Grepped for `$queryRaw/$queryRawUnsafe`: no raw SQL takes user input (the only raw call in scope, `contacts.listVariableSources`, is a tagged template). Exercised the live API at :4000 with a dedicated fixture: workspace `crmbe-audit-1` (recordVisibility=OWN) with ADMIN / CLIENT A / CLIENT B / AGENT / VIEWER users, plus `crmbe-audit-2` with an outsider (seed: `scratchpad/crmbe/seed.mjs`, helper `scratchpad/crmbe/api.sh`). Several findings below were reproduced live before the fix and re-checked after.

Already sound (no change): VIEWER/AGENT write block (central `roleCapabilities`), tenant isolation of every by-id fetch/update/delete (all use `findFirst({ id, workspaceId })` first), `crmReferences` checks on task/activity references, contact export formula escaping, search scoping, public form field validation/honeypot/attribution allow-list, line-item money maths, quote status transitions, gamification dedupe keys.
