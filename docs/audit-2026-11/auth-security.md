# Audit: auth-security

Scope: authentication, sessions, identity, RBAC/tenant middleware, OAuth (Google client + ChatFlow-as-authorization-server), invitations, members, API keys, CORS/headers/rate limits, frontend auth pages.

Method: read every file in scope; wrote a route-walker (patches the `router` Layer to record mount paths and lists every route with its middleware chain) and checked all 475 `/api/v1` routes; exploit-tested the live API with a second tenant, a VIEWER, a second ADMIN and a workspace-less user plus a registered OAuth client; drove login / sign-out / forgot-password / register / invite-accept / consent in Chromium (Playwright).

Route walker result: all 358 `/workspaces/:workspaceId/...` routes run `authenticate` + `workspaceContext`, except `GET|POST /forms/:workspaceId/:slug` (public lead forms, deliberate). Every `/admin/*` route and `/assistant/reindex` run `requireSuperAdmin`. Cross-tenant GETs on members/contacts/api-keys/settings/invitations/conversations and `POST /workspaces/<other>/switch` all answer 403 (checked live).

| AS-2 | High | Google OAuth | services/auth.service.js `findOrCreateGoogleUser`; app.js strategy | Accounts were linked by email without checking Google's `email_verified`. | AS-5 | Medium | Rate limiting | middleware/rateLimit.js | The `countFailuresOnly` limiter (login, signup-verify, reset, oauth token) charged an attempt only on `finish`. | AS-7 | Medium | Sessions | services/auth.service.js `refresh` | Refresh rotation read the token and then deleted it. The frontend now uses a successor token another tab has just stored instead of signing out. HS256 is pinned on every `jwt.verify`. | auth.service.test.js |
| AS-8 | Medium | Account | services/users.service.js `changePassword` | Changing the password left **every other session alive** (refresh tokens kept working for a week), which is exactly when it matters most. Also, a **wrong current password answered 401**, which the client reads as an expired session. It then refreshed, retried and **signed the user out for a typo**. Account deletion with a wrong password did the same. | Fixed: all other refresh tokens are revoked and the caller's own is kept (ProfileView sends it). | AS-9 | Medium | Members | services/members.service.js | Any admin could **demote or remove the workspace owner**. An admin who joined through a shared ADMIN link could take the workspace over. Severity counts: High 4 (AS-1..4), Medium 9 (AS-5..13), Low 9 (AS-14..18, 22..25), Info 4 (AS-19..21, 26). Fixed: 18 of 26.

Verified OK with no change needed: alg=none and forged JWTs are rejected; logout revokes the jti and the refresh token; workspace switching requires membership; `/users/me` PATCH is `.strict()` and whitelisted (no email/role/superAdmin mass-assignment); API keys are SHA-256 hashed, shown once, revocable and scope-enforced (`requireScope` on every public route; legacy null-scope keys cannot reach `authentication:*`); OTPs are CSPRNG with a 10-minute TTL, single use via an atomic claim, and 5-attempt lockout; Google state is HMAC-signed with a 10-minute TTL; the error handler hides 5xx messages in production; body limit is 2 MB JSON; security headers and CSP are present; super-admin is verified against the DB on every request.

## npm audit (backend, --omit=dev)
`npm audit fix --legacy-peer-deps` (no --force) updated the lockfile only: proxy-addr 2.0.8 (critical IP-spoofing advisory), qs 6.17.1, protobufjs 7.6.6, express/body-parser transitive bumps. Full suite stays green (537/537). Remaining, all of which need a major bump:
- **nodemailer ≤10.1.3 (high)**: SMTP DoS / address-parsing advisories. Fix is a major upgrade; recommend scheduling it.
- **zod <4.6.6 (high)**: memory exhaustion on oversized constrained collections. Left on its current major as instructed. Mitigated by the 2 MB body limit and `.max()` on arrays in most schemas.
- **csv-parse <7.0.2 (moderate)**: major upgrade.

## Outside my scope (noticed, not fixed)
1. **/ai/* writes by VIEWER** (`routes/ai.routes.js`): I confirmed live that a VIEWER could create templates through `/ai/template/create`. Another auditor has since added `authorize('CLIENT')` there. Still unchecked: `/ai/workflow/execute` and `/onboarding/chat` (it creates templates and campaigns from chat, needs only membership, and does not apply the VIEWER/AGENT floor).
2. **subscription.service.js `getActiveSubscription`**: lazy `usageCounter.upsert` races under concurrency and fails with P2002 → 500 (reproduced: 5 concurrent invite accepts on a fresh period).
3. **public.routes.js `POST /public/webhooks`**: calls `settingsController.updateSettings` with a hand-built req, so the `settingsSchemas.update` URL validation is bypassed. Check for SSRF and URL validation in the webhooks owner's area.
4. Removing a member does not delete their `TeamMember` rows or their `OAuthConsent` rows for that workspace.
5. The public API has no per-key rate limit.
6. deploy-vps.sh / nginx deployments also need TRUST_PROXY_HOPS set.
