# crm-frontend audit report

Method: seeded the local test workspace (`seed-crm-50.js` piped with the local workspace id. The script hard-codes a production-looking workspace id, see O-1). Then drove every CRM page with Playwright/Chromium at 1440px and 390px, as test@example.com, plus logged-out runs for the public form and Legal pages. A click-every-button sweep ran on all CRM pages. Flows tested end to end: task complete/reopen/bulk/delete/overdue; deal drag, Alt+Arrow and stage select (including Closed Lost with a reason); product CRUD and reactivate; quote create, line items, discount, totals and print; lead search, bulk actions and tasks tab; lead form builder → public URL (logged out) → submit → lead appears; tickets (create, status move, priority); CSV export/import; forecast in Asia/Kolkata and America/Los_Angeles; all 32 resource pages plus 17 categories plus 404s; all Legal slugs.
Many transient 500s in the logs came from the API restarting under `node --watch`, because other auditors were editing the backend at the same time (138 restarts). Each one I re-checked with curl returned 200.

`npx vite build`: passes.

## Outside my scope (not fixed)
- O-1 (backend/scripts) `seed-crm-50.js` hard-codes workspace id `cmrt8hesi000l5lejtvocvic7` ("Sampada Kulkarni's Workspace"), which looks like a real/prod tenant. Run against a prod DATABASE_URL, it writes 50 fake leads into a customer's workspace. `seed-crm.js` seeds **every** workspace and uses `prisma.user.findFirst()` as the owner of all of them, so it creates cross-tenant owner references.
- O-2 (components/Form.jsx) `FInput/FSelect/FTextarea` spread `...rest` after `style`, so any caller passing `style` loses the dark theme style entirely. Other affected call sites: CustomizeBusinessView.jsx:840, 909, 1077; SettingsView.jsx:516, 579. Fix: merge `style` into fieldStyle.
- O-3 (components/Btn.jsx) Btn drops `aria-label`, `title` and other props (only children/variant/size/onClick/style/disabled/type), so icon-only Btns have no accessible name.
- O-4 (components/Modal.jsx) There is no `role="dialog"`/`aria-modal`, no Escape-to-close, and no focus trap (useFocusTrap exists in lib but isn't used here).
- O-5 (backend tickets) Ticket categories in crm-customization carry `slaHours` (e.g. Account Access 4h), and the new-ticket datalist shows them, but `tickets.service` computes SLA only from priority (`SLA_HOURS`). The SLA shown to the user is not the one enforced. A category priority of `MEDIUM` isn't a valid ticket priority.
- O-6 (backend crm-analytics) `winRate90d` counts only deals with `closedAt` in 90d. Seeded CLOSED_LOST deals had null `closedAt`, so it reported a 100% win rate. Real stage changes set closedAt, so this mainly affects imported or seeded data. Consider using `updatedAt`/stage-change history as a fallback.
- O-7 Tasks API has no `lead.contact` include, so the Tasks page can only name a lead when `contactId` is also set on the task.
- O-8 CrmSalesInboxView still uses `alert()` for success/error on template send, campaign launch, sequence enroll and delete. That blocks the UI and is inaccessible; it should use inline banners like the rest of the CRM.
- O-9 The "Ask your CRM" floating button (global) covers the last table row's actions (e.g. the task delete icon) at 1440px.
