# campaigns-billing audit

Scope: campaigns (create/CSV/variables/launch/pause/resume/cancel/retry/worker), wallet, Razorpay (top-up, plan, add-on), subscription usage, segments-as-audience, analytics.
Tested live: API (curl) plus a Playwright walk of the Create Campaign wizard (CSV upload with BOM + `;` delimiter + "NAME"/"Mobile Number" headers + duplicate/invalid/formula rows → variable mapping → schedule → Go Live), the Payments tabs and Recharge, and the Analytics, User Analytics and Chat Analytics pages. Meta sends fail with the dummy credentials; the campaign completed, both recipients were FAILED / NOT_CHARGED and the ₹0.32 was refunded, with the ledger showing the debit and the refund.

Tests: `npm test` 544/544 pass. `npx vite build` OK. New tests: `src/services/campaignMoney.test.js` (12, real DB), `src/workers/campaign.worker.test.js` (4, real DB, Meta faked), plus 2 added to `src/services/contactImportAttributes.test.js`.

Reviewed and found OK: wallet debit/credit (FOR UPDATE row lock, unique idempotency key, never negative, paise rounding); per-recipient claims (PENDING→SENDING, RETRYING→IN_PROGRESS) under 2 workers; billing claim `billedAt: null`; settlement arithmetic; opt-out exclusion at launch and per send; status webhook monotonic updates; the top-up order amount is read back from Razorpay and `notes.workspaceId`/`type` are checked; analytics queries are all `workspaceId`-scoped, `days` is whitelisted and divisions are guarded (live-probed `days=abc,-5,0,1e9`: all 200).

Not fixed / notes:
- There is no Razorpay webhook endpoint at all. Crediting relies on the browser calling verify, so a closed tab after payment means no credit until someone reconciles. Adding one needs a webhook secret and config.
- Cancelling mid-send settles immediately; a send already in flight at that moment can then go out unpaid (at most one message per running loop).
- The wallet banner's "≈ N messages" uses `Workspace.costPerMessage` (0.92), not the template category rate the campaign is charged (e.g. 0.16).
- A Meta HTTP failure with no Meta error body is shown raw ("Request failed with status code 403").
- `getWalletSummary` "today" and delivery-day buckets use the server's timezone.

Outside my scope (noticed, not touched):
- Segments and clusters routes have no `authorize()`, so any member/viewer can create or delete them (decide per RBAC owner).
- Leading-zero local numbers ("098…") are stored as `+098…`, which Meta will reject (contacts owner).
- The dev environment restarts the API often (other auditors' edits), which shows up as transient 500s through the Vite proxy.
